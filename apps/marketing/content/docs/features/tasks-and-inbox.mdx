**Inbox, Kanban, Tasks to-dos and delegation are available in Stable 1.0.1.** A to-do is something you want done; a chat is the conversation where an agent works on it.

## Add and delegate a to-do

Open **Tasks** and add a title. Select the item to open its card and edit its note, project, priority, and due date. Tasks can exist without a project or agent.

Select a provider, model, effort, and project or folder first. To reuse a chat, select it under **More options**. Then press **Start** to delegate immediately. The agent receives the current title and note. The item follows the chat's state: running, needs you, ready for review, or failed. Its card shows recent activity, pending approval controls, and the latest reply. Review the result before marking the to-do done.

Use the **List / Kanban** switch to change views; Synara remembers the selection.

## Use the attention board

Kanban's **Attention** view groups chat cards into **Draft**, **In Progress**, **Awaiting you**, and **Done**. Approvals, unanswered questions, failures, and stalled work surface in Awaiting you. **Classic** retains the three-column layout. Review status depends on a live-confirmed open pull request in a dedicated worktree.

Choose **Send as goal** on a draft to start it with a persistent goal. Long goals use managed file references rather than being silently shortened. Goals can contain up to 120,000 characters; larger input is rejected. The regular chat permissions and [goal controls](/docs/features/thread-goals) still apply.

Agents can inspect and operate durable Kanban cards through the [Agent Gateway](/docs/workflows/agent-gateway), scoped to their ordinary project. Local unsent composer drafts remain client-only. Kanban tools manage chat cards; the separate to-do tools maintain Tasks records.

## Start the day in Inbox

Inbox brings together running chats, work needing attention, review requests, and recently finished work beside a recap of your agent activity. The working day starts at **4am**. Recaps use recorded local activity and available provider-attributed usage; missing telemetry is not invented.

In Beta, Inbox also shows due and overdue Tasks to-dos. Adding a task makes it due on today's calendar date; **All tasks** opens the full backlog. These to-do controls are unavailable in Stable.

In Beta, select an Inbox task to use the same editing and delegation card as Tasks. Use its attention groups to decide which approval, question, failure, or finished result to inspect next. A finished agent turn is a review opportunity, not proof the requested work is correct.

See [Hubs](/docs/features/hubs) when several workers need shared instructions, memory, and one coordinator.

## Maintain to-dos from a chat

In 1.0.2-beta.1, supported sessions can use `synara_create_todo`, `synara_list_todos` and `synara_update_todo` to maintain the same list. Ask the agent to record a task for later, set its notes, priority, calendar due date or project, mark it complete or reopen it. Creating a to-do does not create a chat or start an agent; use **Start** to delegate it.

Writes require an active caller turn and the thread's write capability. A create request uses a stable `requestId` so retrying does not add a duplicate. Listing returns at most 200 items and reports truncation; list notes are previews of up to 500 characters. Selecting a to-do by ID returns its full notes. No delete tool is exposed.

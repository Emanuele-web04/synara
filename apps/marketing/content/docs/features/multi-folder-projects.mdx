---
title: Multi-folder projects
description: Work across related folders with Codex, Claude or Antigravity, with explicit limits for Git and recovery.
---

Create one project for a frontend, API and shared package that change together.

## Choose source folders

When creating a project, add folders under **Source folders**. Use **Make primary** to choose the working directory. The primary folder retains ordinary single-folder project behavior. The agent receives the other folders as additional accessible directories and a list of their absolute paths.

Every folder must already exist. Duplicate and nested folders are refused, including aliases resolved to the same folder. Add or remove additional folders later from **Edit project**; a running chat picks up the new set on its next turn. Move the primary folder with **Change project path**.

## Provider and environment limits

**Codex, Claude and Antigravity** support additional folders. Other providers refuse the chat rather than silently dropping directory access. Local and Worktree modes are supported. A worktree isolates only the primary folder; edits in the other folders apply directly. Provider permission and sandbox policies still apply. Antigravity receives each extra folder through its native `agy acp --add-dir` flag.

## Review and recover changes

Git actions, checkpoint diffs, and File Undo cover **only the primary folder**. Review, commit and recover edits in additional folders separately, using each folder's own tools and Git history. Multi-folder access does not provide multi-repository checkpoints or atomic Undo.

See [Organize & navigate](/docs/features/organize), [Worktrees](/docs/workflows/worktrees), and [Provider accounts](/docs/features/provider-accounts).

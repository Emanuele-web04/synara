---
title: Terminal panels
description: Use the main terminal and independent right-dock tabs, run project actions, and recover sessions.
---

Synara 1.0.1-beta.2 keeps one main-view terminal per chat and supports multiple independent right-dock terminal tabs. Every **+ → Terminal** creates its own shell. Switching tabs preserves sessions; closing or exiting one leaves the others running. Dock tabs and session identities survive reload. Use `mod+j` to toggle the panel, or `mod+shift+j` for the full-width workspace. In that workspace, `ctrl+1` and `ctrl+2` switch between terminal and chat. Opening the terminal again focuses the existing session.

## Run a project action

Project actions open a fresh session in the right dock using the chat's actual working directory and runtime environment, keeping the center chat and composer visible, including in split chats. They replace only the selected idle dock terminal. If it is busy, stop its work before running another action there; other dock sessions remain running. The server checks activity even after a reload, and refuses an action when it cannot establish that the session is idle. Opening a workspace path uses the same idle check before sending shell navigation input.

## Close and reopen

An explicit close ends the terminal session. If closing fails, the pane stays visible and usable. Reopening after close or shell exit creates a new session identity, so delayed cleanup cannot terminate the replacement shell. Hiding the panel is separate from closing the session.

## Upgrade an older terminal layout

Nested terminal tabs, groups, splits, and the bottom drawer are removed. Synara retains the last active terminal. Retired nested sessions close only after the server verifies they are idle; their saved history is preserved. Busy sessions or sessions whose activity cannot be checked remain pending for the next mount. Old terminal-split keybindings no longer intercept shell shortcuts.

See [Keyboard shortcuts](/docs/reference/keyboard-shortcuts) for the current keymap and [provider accounts](/docs/features/provider-accounts) for account-specific terminal commands.

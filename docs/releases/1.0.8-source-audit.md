## Durable documentation and gates

- `docs/editor/intelligence.md`, shared `betaFeatures.ts`, server `nativeEditorGate.ts`, web `betaFeatures.ts`, and `BETA.md` agree: native editing and `editor.*` RPCs are Beta-only. Stable retains Pierre. The public workspace editor guide explains languages, commands, shared buffers, multi-file save limits and debugger execution. Existing navigation and the overview/Beta/shortcuts guides link it; no duplicate guide is needed.
- `docs/hubs.md` already documents original requests, role provenance, frozen task keys, idempotent retries and queue/steer semantics. Public Hubs documentation now mirrors the durable behavior.
- `docs/providers.md` already covers handoff fallback and transcript omissions. Public handoff guidance now covers Send/Continue/Implement, queued provider selection, background-task refusal and recovery warnings.
- `docs/core-concepts.md` documents captured diffs and Space-scoped close navigation. Public editor, navigation, subagent, terminal, Safari, simulator and customization guides cover the affected controls and ownership limits.
- `docs/sqlite-space-reclamation.md` explains thresholds, clean shutdown, bounded process ownership and deferred conversion. Public runtime troubleshooting links behavior to safe recovery rather than promising a disk-size reduction.
- No migration file changed in this range. The Windows process boundary check is required for debugger cleanup and shared teardown changes. No provider/model selection or Beta feature gate is changed by preparation.
- The actual production website is a separate Git checkout linked to Vercel. Its dirty operator checkout is preserved; release documentation and notes are prepared in a clean clone. The maintained application mirror receives the same audited content.

## Qualification boundary

Release preparation changes only versions, lockfile workspace versions, release text and documentation. Existing in-app and website changelog components are reused; no layout or control is added. All visible release text is within the authorized release scope.

Local results, candidate SHAs, workflow attempts and public asset identities are recorded outside tracked release inputs and in curated GitHub notes. Exact-tag CI must qualify all test shards, portable inputs, four native packages, provenance, macOS signing/notarization and Intel startup, plus Windows Defender/startup with the exact version-scoped unsigned exception. Manual installation/upgrades, browser-download reputation and live provider/microphone behavior remain unqualified.

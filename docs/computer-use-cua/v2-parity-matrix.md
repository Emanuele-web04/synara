# Codex vs Synara computer use parity matrix

> Historical comparison, with unverified third-party claims and earlier Synara
> revisions. It is not the current capability inventory or release evidence.
> For shipped routes, unsupported Spaces management and remaining qualification,
> use the [current implementation](README.md).

## Scope

This doc maps each Codex computer use capability to the Synara equivalent on branch `agent/computer-use-preview` at native revision 20 and driver 0.28.2. Codex claims come from third party reconstructions and local binary scans in the mega handoff, so each is marked unverified. Ours claims come from the tool surface, the backend, the desktop host, and repo docs. The milestone tool set and scroll v2 are verified live on TextEdit on this VM at rev 16; background drag and the hidden-workspace lifecycle are verified live at rev 17; the rev-18 AX observer settle passed a live embedded-daemon smoke (TextEdit application scope, Safari window scope, foreign-window and dead-pid refusals) plus unit and contract tests — no signed-app GUI run has qualified the full Synara path yet; three concurrent real-app targets with foreground isolation are verified live at rev 17 via the external trusted host (`evidence/rev17-realapp-3target-2026-09-22-*` — three distinct TextEdit pids, concurrent `set_value`, all `confirmed` with `value_readback`, frontmost untouched). Off-Space semantic input is now resolved (2026-10-02, `space-management-findings.md`): direct input into a window on an inactive Space is impossible at the OS level — the window leaves the app's AX hierarchy entirely — but Mission Control is AX-drivable through Dock's entitlement, so the agent can create a managed Space (`add desktop` button → `space 62 type=0` verified), switch Spaces (Spaces-Bar AX press `1→53` verified; app-activation switching verified), then act normally on the now-active space. The signed-app fresh-TCC run remains uncertified. The browser/CDP family is wired through the driver as `computer_browser_*`; the Chrome extension path stays deferred. `computer_select_text` is verified live at rev 20 on the packaged driver (hidden TextEdit, `value_readback` confirmed and independently echoed by a System Events `AXSelectedText` read on the exact window; out-of-bounds refused `ax_action_refused` unclamped; operator front untouched).

## Gap summary

Ranked by user pain and milestone order. Codex side items stay unverified until measured against the shipping binary.

1. Type text isolation (RESOLVED 2026-09-17): web-content fields route through verified `set_value` compose; the G5 three-window fixture passed 10x with sentinel focus held. The rev 15 fixture proved the original failure (dispatched unknown).
2. Synthetic focus belief (DEAD by experiment): six belief stages including a real `_SLPSSetFrontProcessWithOptions` front flip cannot manufacture a key window; process-scoped `CGEventPostToPid` never reaches an inactive renderer. See the status block below.
3. Scroll v2 (LANDED 2026-09-17, native rev 16): two axes plus modifiers in one pixel-unit wheel gesture, macOS before/after measurement inside the 2-leg/3-capture budget, and route-keyed gearing with a durable per-app file. Live-verified on TextEdit; the NSScrollView horizontal limitation is documented in the scroll row.
4. Menus and window frames (LANDED 2026-09-17): `computer_invoke_menu` and `computer_set_window_frame` are exposed, approval-gated, and verified live on TextEdit.
5. Settle and observation. LANDED at native rev 18 (live embedded-daemon smoke plus unit/contract tests; the full Synara path is not yet qualified in a signed-app GUI run): the read-only `wait_for_settle` driver tool runs an AX observer against the target's application element — window-scoped when `window_id` is passed — resolves on `quiet_ms` of notification silence, and extends to `timeout_ms` on a churning surface. Post-action observation prefers it whenever the action's window is known, `computer_wait` exposes it as `{window_id, settle:true}`, an older or refusing driver is cached as unsupported and falls back to the fixed settle, and `SYNARA_CUA_CONDITIONAL_SETTLE` proof-skipping still runs ahead of the observer. `SYNARA_CUA_ACTION_SETTLE_MS` continues to govern the fixed fallback.
6. Background drag (LANDED 2026-09-22, native rev 17): window-local stamped press-drag-release delivers to inactive AppKit windows with the operator's front process untouched; `computer_drag` defaults to `delivery_mode=background`, foreground stays the explicit fallback, and older drivers fail closed. Electron remains dead (see the status block).
7. Synthetic key activation. Raising a window just to aim keys steals focus. Target P1.
8. Screenshots and Spaces certification. Freshness refusals and routing exist in source but are uncertified at rev 16. Target P1.
9. Per app approvals and always allow. Needs a safety decision before any build. Target P1 for the decision, P2 for build.
10. Secondary actions beyond AXPress (LANDED): `computer_perform_action` now admits `press` (with `AXPress` kept as the legacy spelling), `open`, `show_menu`/`menu`, `pick`, `confirm` and `cancel`, each dispatched through the driver's `click` element-token `action` recipe and refused `not-dispatched` when the resolved element does not advertise the matching AX action. AX names outside that six-name recipe still refuse.
11. Click recipe breadth. Native versus Chromium recipe selection exists; masked activation spiked 2026-09-23 ([findings](masked-activation-findings.md)): the foreign level-raise recipe is likely SIP-gated (every probed foreign mutation no-ops on this box), but an own-window frozen-shield design needs zero foreign writes and is self-cleaning on driver death — buildable behind a canary + per-app-class opt-in. Target P2.
12. Cursor richness and multi cursor. Per-agent identity landed: each attributed call rides an `agent·<label>·<thread>` session, so parallel threads show distinct labeled cursors in the one overlay (compact mode tints the badge, not the arrow). Animated theme richness is still missing. Remaining target P2.
13. `select_text` and `press_key` coverage. Small gaps with workarounds; `computer_list_apps` landed 2026-09-17. Target P2. `press_key` narrowed 2026-09-23: the driver keymap was audited end to end, xdotool spellings (`page_up`/`page_down`/`caps_lock`/left-modifier forms) now resolve Synara-side, and `kp_*`/`f13`-`f20`/`menu`/`help` landed at native rev 19 via `native-keymap.diff`. `insert`/`ins` stay refused — macOS has no Insert key. `select_text` landed 2026-09-23: exact `AXSelectedTextRange` write on a semantic element target, verified only by attribute read-back, marker-only web content refused pre-dispatch, native rev 20, folded into `0001-synara-native.patch` — see `docs/computer-use-cua/native-select-text.md`.
14. Locked use and history. The locked-use safety decision landed: fail closed on lock/sleep/session resign and resume by explicit re-auth (unlocked session + fresh observation + republished task consent), never silent continuation — auto-unlock parity stays intentionally absent. History still needs a privacy decision first. Target Later.
15. Chrome CDP path. The driver browser family now ships as `computer_browser_*` (see the status update); the extension route stays deferred. Revisit only after native parity lands.

## Status update — 2026-09-17 live experiments (this VM, full TCC)

The gap summary above predates the decisive input matrix. Verified results:

- **Gap 1 (type text isolation) — RESOLVED.** Web-content fields now route
  through verified `set_value` compose; three-window same-pid typing passes
  with `verified/confirmed`, serialized per-pid lane, zero focus steal.
- **Gap 2 (synthetic focus belief) — DEAD by experiment.** Six belief stages
  including a real `_SLPSSetFrontProcessWithOptions` front flip cannot
  manufacture a key window; process-scoped `CGEventPostToPid` (keys, moves,
  wheel) never reaches an inactive renderer. Belief work is cancelled.
- **Gap 6 (background drag) and 7 (synthetic key activation) —
  RECHARACTERIZED.** No background CGEvent path exists on inactive Electron.
  Real input events exist only through `delivery_mode=foreground`
  (short-lived front excursion + restore, operator-invisible): verified for
  keys, clicks (DOM focus + mouseenter), and wheel. Background = semantic AX
  writes only.
- **Gap 6 (background drag) — LANDS on AppKit (experimental rev 17,
  2026-09-22).** The driver patch that removes upstream's unconditional
  `background_unavailable` drag gate is verified: window-local stamped
  press-drag-release selects text in an inactive Cocoa window with the
  operator's front process untouched (input-matrix-2026-09-17.md). Synara
  admits `delivery_mode=background` on `computer_drag` for exact
  `cua:<pid>:<window_id>` targets with both endpoints in-window; drivers
  without the patch refuse `background_unavailable` → `not-dispatched`, and
  foreground stays the fallback for surfaces that drop background events.
  Electron remains dead for CGEvent paths — the recharacterization above
  still holds there. (2026-09-18 addendum: the AX-semantic path is NOT
  dead on Chromium — the driver self-enables
  `AXManualAccessibility`/`AXEnhancedUserInterface` and `set_value`/
  readback/`get_window_state` work on a hidden real Chrome, certified by
  the `chromium-semantic` live-cert row. The dead claim applies to
  process-scoped event injection only.)
- **Gap 4 (menus/frames) — WIRED.** `invoke_menu`, `set_window_frame`,
  `list_apps`, `verify_state`, `zoom`, `kill_app` verified live on TextEdit
  and shipped through protocol/backend/manager/gateway as
  `computer_invoke_menu`, `computer_set_window_frame`, `computer_list_apps`,
  `computer_verify_state`, `computer_zoom`, `computer_kill_app`. Mutations
  are approval-gated with second-app consent and Synara-side read-back;
  `verify_state` returns a tri-state that cannot contradict the scoped
  observation contract.
- **Gap 3 (scroll v2): LANDED at rev 16.** The rev-15 finding stood:
  background scroll returns `background_unavailable` on Electron and
  foreground scroll delivers real DOM wheel events. The rev-16
  implementation adds the two-axis plus modifier gesture and macOS
  measurement; details below.
- **Hidden-workspace lifecycle (rev 17) — WIRED.** `launch_app` grew a
  `hidden` flag (the `open -j` posture), `set_app_visibility` hides/unhides a
  running app by pid, and `set_window_minimized` minimizes/restores one exact
  window — all verified live on macOS 26.5.2 without activation, focus steal,
  or Space switches. Shipped as `computer_launch_app({hidden:true})`,
  `computer_set_app_visibility`, and `computer_set_window_minimized`, all
  approval-gated with the same second-app consent as the frame/menu tools;
  the visibility pair is reported `confirmed` only on the driver's own
  AXHidden/AXMinimized read-back evidence. Hidden apps and windows keep
  answering the semantic tools; only the raw coordinate stream still needs a
  visible target.
- **Gap 15 (Chrome CDP path) — WIRED through the driver, not an extension.**
  The pinned driver's browser family is exposed as nine
  `computer_browser_*` tools behind `computer:control` and the same
  task-scoped approval gate as the desktop family: `state` (bind + snapshot),
  `prepare`, `navigate`, `click`, `type`, `dialog`, `upload`, `download`,
  `pointer`. CDP `Input.dispatch*` reaches background Chromium renderers that
  process-scoped CGEvents cannot — the fix path for the Electron gap above.
  Upload/download paths are canonicalized inside the thread workspace; driver
  refusals (`status:"refused"`) reach the model as results, not tool errors.
  Wiring: `docs/computer-use-cua/browser-surface-spec.md`.
- **Gap 13 (press_key coverage) — NARROWED (keymap audit + alias map).** The
  driver gate is one match table, `key_name_to_code` in
  `platform-macos/src/input/keyboard.rs`: nav/editing keys, f1-f12, every
  letter/digit/punctuation and the five modifiers already had keycodes.

  `page_up`/`pgup`/`prior`→pageup, `page_down`/`pgdn`/`next`→pagedown,
  `caps_lock`→capslock, `super_l`/`win`→command, `shift_l`/`ctrl_l`/`alt_l`
  (and `option_l`)→the generic modifier codes — while names with no macOS
  keycode mapping yet (`kp_*` keypad, `f13`-`f20`, `menu`, `help`) pass

  and `native-keymap.diff` (next native rev) lights them up with no second
  Synara change. `insert`/`ins` refuse `unsupported_operation` — macOS has
  no Insert key, and `help` (the physical key PC Insert produces) is kept
  under its own name rather than aliased. Right-side modifier spellings stay
  driver-refused until the keymap carries the right-key codes.

## Status update: 2026-09-17/18, native rev 17

- **Two-axis + modifier scroll is live (rev 16).** `scroll` accepts
  `delta_x`/`delta_y`/`modifiers`; delta mode posts pixel-unit wheel
  events, a two-axis-plus-modifier request dispatches as one event, and a
  pid-only scroll refuses.
- **Measured limits.** Requests quantize to 120-pixel notches, 50 per axis
  per dispatch; the tool layer still clamps to half the captured frame and
  still refuses a fourth unchanged scroll. TextEdit ignores horizontal
  wheel deltas: NSScrollView wants continuous trackpad deltas, so
  horizontal wheel scroll is limited there by the toolkit, not by us.
- **Keystroke scroll is unreachable** through the Synara-patched driver:
  admission requires an exact pid plus window_id, so the delta/modifier
  refusal on the driver's keystroke path is defense-in-depth, not a live
  gate.
- **Electron background scroll and type via CGEvent are dead.** Upstream
  refuses background scroll for Electron outright, and process-scoped
  CGEvent posts never reach an inactive renderer. The `browser_*` CDP
  surface now covers browser-class apps; computer use stays the native-app
  fallback.
- **Space management is proven blocked for an unentitled process.**
  `SLSSpaceCreate` produces orphaned type-3 spaces that never attach;
  every move/add/remove/set-current variant (including the
  `SLSBridged*Operation` WM bridge) is a verified no-op for foreign
  windows under SIP on macOS 26.5.2 — the boundary is Dock's
  `com.apple.private.skylight.universal-owner` entitlement. The supported
  isolation surface is the hidden-workspace lifecycle (rev 17):
  `launch_app {hidden:true}` + `set_app_visibility` +
  `set_window_minimized`, with semantic AX input confirmed working on
  hidden/minimized windows. See space-management-findings.md.
- **Silent launch verified and landed.** `open -g -n -a` and the driver's
  own `launch_app` never steal focus; `hidden:true` additionally skips
  rendering entirely.
- **Hidden-workspace lifecycle (rev 17).** New driver tools:
  `set_window_minimized` (exact pid+window_id, AXMinimized readback) and
  `set_app_visibility` (pid, AXHidden + isHidden readback); `launch_app`
  accepts `hidden`. Verified end-to-end: hidden TextEdit accepted
  `set_value` with `effect:confirmed`, frontmost stayed ghostty.
- **Browser surface (CDP family).** The nine `browser_*`/`get_browser_state`
  tools ship as `computer_browser_*` on per-thread lifecycle sessions under
  a persistent control transport — live-smoked end to end against the rev-17
  driver (prepare → navigate → snapshot; `browser_route_unavailable` verbatim
  on non-CDP windows). See browser-surface-spec.md.

Driver surface inventory (58 tools at rev 20): Synara exposes the full
agent-facing `computer_*` desktop set plus the `computer_browser_*` family.
Remaining host-internal by decision: reads (`health_report`, `get_config`,
`get_recording_state`, `get_session`, `get_session_state`, `list_sessions`,
`check_for_update`, `history_status`/`history_query`), mutations
(`set_config`, `set_agent_cursor_enabled`/`motion`/`theme`,
`start_session`/`end_session`/`escalate_session`,
`start_recording`/`stop_recording`, `replay_trajectory`, `install_ffmpeg`),
and the legacy `page` tool. `get_accessibility_tree` and `get_cursor_position`
are allowlisted reads used internally by the backend, not separate agent
tools. The browser family rides the same `computer:control` capability and
task-scoped approval gate as the desktop tools; the driver's endpoint grant
stays a separate consent axis handled inside `browser_prepare`.
